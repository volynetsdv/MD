## 1. Науково-теоретичний базис та постановка задачі

Програмний комплекс призначено для вирішення науково-прикладної задачі автоматизованого розпізнавання малорозмірних об'єктів (піхота, легкова та важка техніка, бронетехніка, артилерійські комплекси, плавзасоби) на ортофотопланах та панорамних кадрах аерофотозйомки з роздільною здатністю від 4K ($3840 \times 2160$ px) до 8K+ ($7680 \times 4320$ px та оглядових панорам понад 13 000 px) на периферійних (Edge) системах в автономному польовому режимі без залучення хмарних обчислень.

### Науково-методологічна формалізація:
* **Об'єкт дослідження:** Процес автоматизованого розпізнавання малорозмірних об'єктів на аерофотознімках надвисокої роздільної здатності на апаратних платформах із обмеженими обчислювальними ресурсами.
* **Предмет дослідження:** Методи, алгоритми та програмні моделі просторової динамічної декомпозиції зображень (тайлінгу) з адаптацією геометричних параметрів під поточний апаратний стан системи та просторово-висотний контекст зйомки.
* **Наукова новизна:** **Удосконалено** метод просторової фрагментації аерофотознімків шляхом розробки моделі апаратно-усвідомленої динамічної декомпозиції, яка, на відміну від статичних підходів (SAHI), адаптивно визначає розрахунковий розмір вікна ($T_{\text{calc}}$) та коефіцієнт перекриття ($O_{\text{lap}}$) на основі доступного ліміту відеопам'яті ($\text{VRAM}_{\text{avail}}$) і висоти польоту $H$. Це усуває обчислювальну надлишковість на фонових областях, нівелює ризик критичних відмов вичерпання пам'яті (CUDA Out-Of-Memory) та підвищує пропускну здатність конвеєра до 5.45 разів.
* **Практичне значення:** **Спроектовано та реалізовано** кросплатформний автономний програмний комплекс робочої станції оператора (Linux/Windows), що забезпечує субсекундний інференс 8K кадру ($< 300\text{--}450\text{ мс}$) за рахунок прямого конструювання тензорів у пам'яті GPU, мінімізації накладних витрат шини PCIe та неруйнівного векторного рендерингу оверлею.

## 2. Фундаментальні архітектурні інваріанти

Архітектура комплексу підпорядкована суворим концептуальним інваріантам, що забезпечують теоретичну збіжність, детермінізм виділення пам'яті та ліквідацію апаратних заторів:

### 1. Односпрямований Host-to-Device транзит та нульовий зворотний PCIe-трафік (Zero PCIe Readback)
- Первинний повнорозмірний растровий масив транслюється в пам'ять графічного прискорювача (VRAM) **рівно один раз** (`cudaMemcpyHostToDevice`).
- Для запобігання деградації пропускної здатності системної шини **фізично виключено зворотну передачу растрових даних із пам'яті прискорювача на хост (Host RAM)**. Графічний процесор повертає виключно компактний тензор числових метаданих детекції:
  $$\mathbf{D} = \{x, y, w, h, \text{conf}, \text{class\_id}\}$$
  Це знижує інтерфейсні затримки передачі до $O(N)$, де $N$ — кількість виявлених цілей, мінімізуючи трафік шини на 99.8% порівняно з ретрансляцією модифікованого растру.

### 2. Внутрішньопам'ятна безкопійна декомпозиція (In-Memory Zero-Copy Slicing)
- Категорична відмова від проміжного дискового кешування (відсутність операцій запису тимчасових растрових файлів `.jpg`/`.png` на SSD/NVMe).
- Формування підмасивів плиток виконується безпосередньо у виділеному пулі пам'яті GPU за допомогою низькорівневого CUDA-ядра (`cuda_slicer.cu`), що здійснює білінійну інтерполяцію та нормалізацію субтензорів «на місці», або через механізм представлень NumPy (`strided array views`) в оперативній пам'яті хоста. 

### 3. Пакетний скринінг диск-в-диск (Batch Triage Disk-to-Disk)
- Під час автоматизованої фільтрації великих масивів розвідувальних даних алгоритм селекції кадрів із позитивними детекціями ($\ge 1$ виявленої цілі) виконує передачу вихідних графічних файлів у цільовий каталог **безпосередньо засобами файлової підсистеми хоста (`shutil.copy2`)**.
- Виключається вивантаження растру з пам'яті GPU для повторного збереження. Структуровані координатні дані детекцій серіалізуються поруч із еталонним зображенням у вигляді ізольованого файлу дескрипторів `<stem>.json`.

### 4. Неруйнівний векторний оверлей (Metadata-Driven Non-Destructive Overlay)
- Графічний рушій робочої станції (`QGraphicsView` / `QGraphicsScene`) реалізує просторове розмежування шарів візуалізації:
  - **Базовий шар ($Z = 0$):** Еталонне незмінне растрове зображення вхідного аерофотознімка.
  - **Векторний шар ($Z \ge 10$):** Аналітичні векторні примітиви (`QGraphicsRectItem`, маркування класів).
- Рендеринг маркерів виконується із застосуванням косметичного пера (`QPen.setCosmetic(True)`), що гарантує інваріантну товщину контуру (2 px) незалежно від поточного масштабного коефіцієнта перегляду ($0.02\times$ -- $50\times$) без деструктивної зміни вихідних спектральних даних знімка.

## 4. Наскрізний конвеєр: динамічна декомпозиція, навчання та мультимасштабний експорт

Архітектура навчання та підготовки вибірок побудована за принципом DRY: модуль підготовки даних `dataset_slicer.py` використовує ідентичні математичні інваріанти розрахунку сітки, що й робочий модуль інференсу.

### Системні вимоги та середовище розгортання:
- **Обчислювальний прискорювач:** Графічний процесор NVIDIA з підтримкою CUDA Compute Capability $\ge 7.0$ (архітектури Turing, Ampere, Ada Lovelace, Blackwell), рекомендований обсяг VRAM $\ge 8\text{--}12\text{ ГБ}$ для навчання та калібрування.
- **Системне програмне забезпечення:** ОС Linux (Ubuntu 22.04 LTS / DevContainer) або Windows 10/11, Python 3.10+, CUDA Toolkit 12.x/13.x, cuDNN 9.x, TensorRT 10.x/11.x.
- **Python-бібліотеки:** `torch`, `torchvision`, `ultralytics`, `opencv-python`, `onnx`, `onnxruntime-gpu`, `pybind11`.

### Структуризація вхідних даних:
Підтримуються нормалізовані конвенції розмітки:
1. **YOLO-HBB:** Горизонтальні рамки (<class_id> <cx> <cy> <w> <h>) у діапазоні $[0.0, 1.0]$.
2. **DOTA v1.0 / v1.5 / v2.0:** 8-точкові полігональні контури ($x_1, y_1, \dots, x_4, y_4, \text{class\_name}, \text{difficult}$).
3. **YOLO-OBB (Oriented Bounding Boxes):** Орієнтовані обмежувальні рамки, що трансформуються в ортогональні описані прямокутники.

---

### Крок 1. Нарізка датасету (`train_pipeline/dataset_slicer.py`)
Скрипт розбиває панорами високої роздільної здатності на перекривні плитки відповідно до параметрів висоти польоту, фільтрує фрагменти цілей, що потрапили на край зрізу, та формує готовий каталог з `dataset.yaml`.

#### Повна робоча команда:
```bash
python3 train_pipeline/dataset_slicer.py \
    --image-dir data/dota_v1.5/images \
    --annotation-dir data/dota_v1.5/labels \
    --output-dir data/sliced_dota \
    --format auto \
    --altitude 120.0 \
    --vram-mb 2048 \
    --min-area-ratio 0.25 \
    --split train \
    --workers 8
```

#### Параметри:
- `--image-dir` (`-i`): Шлях до каталогу з вихідними зображеннями (.jpg, .png, .tif).
- `--annotation-dir` (`-a`): Шлях до каталогу з текстовими анотаціями.
- `--output-dir` (`-o`): Папка призначення, куди записуються плитки, мітки та конфігурація `dataset.yaml`.
- `--format` (`-f`): Формат розмітки (`auto`, `yolo`, `yolo_obb`, `dota`).
- `--altitude`: Розрахункова висота польоту (м) для розрахунку коефіцієнта перекриття $O_{\text{lap}}$.
- `--min-area-ratio`: Поріг збереження цілі (відсікає граничні фрагменти, якщо збережена площа $< 25\%$).
- `--target-size`: Примусова фіксація розміру плитки (320, 416, 512, 640).
- `--workers` (`-w`): Кількість паралельних потоків обробки.

**Результат виконання**: Генерація фрагментованого набору даних, дескриптора структури dataset.yaml та системного метафайлу slicing_meta.json із зафіксованими параметрами $M_{\text{selected}}$ і $O_{\text{lap}}$. 

---

### Крок 2. Оптимізоване навчання нейромережі (`train_pipeline/train.py`)
Скрипт читає згенерований `slicing_meta.json`, встановлює цільовий розмір вхідного тензора, розраховує безпечний розмір пакета (Batch Size) під наявний бюджет пам'яті GPU для запобігання CUDA OOM та ініціалізує оптимізаційний процес.

#### Повна робоча команда:
```bash
python3 train_pipeline/train.py \
    --data data/sliced_dota \
    --model yolo26s.pt \
    --epochs 50 \
    --batch auto \
    --device 0 \
    --workers 8 \
    --project runs/train \
    --name aerial_yolo_train
```

#### Параметри:
- `--data` (`-d`): Шлях до каталогу нарізаного датасету (де знаходяться `dataset.yaml` та `slicing_meta.json`).
- `--model` (`-m`): Базові ваги або архітектура (`yolov8s.pt`, `yolo11s.pt`, `yolo26s.pt`).
- `--epochs` (`-e`): Кількість епох навчання (за замовчуванням: 50).
- `--batch` (`-b`): Розмір батчу або `auto` для автоматичного адаптивного розрахунку.
- `--device`: Індекс GPU (`0`, `cuda:0`) або `cpu`.
- `--dry-run`: Режим попередньої перевірки конфігурації без запуску важкого навчання.

### Крок 3. Мультимасштабний експорт та апаратне квантування (`scripts/export_profiles.py`)
Перетворює контрольний чекпоінт PyTorch у дискретний пул уніфікованих статичних моделей ONNX (opset 17, batch=1) для роздільностей $\{320, 416, 512, 640\}$ px і компілює апаратно-специфічні плани TensorRT (.engine).

#### Експорт пулу моделей у напівточність (FP16):
```bash
python3 scripts/export_profiles.py \
    --weights runs/train/aerial_yolo_train/weights/best.pt \
    --output-dir models/ \
    --fp16 \
    --workspace 2048 \
    --opset 17
```

#### Цілочисельне квантування (INT8 Post-Training Quantization з калібруванням):
```bash
python3 scripts/export_profiles.py \
    --weights runs/train/aerial_yolo_train/weights/best.pt \
    --output-dir models/ \
    --int8 \
    --calib-dir data/sliced_dota/images/train \
    --workspace 2048
```

#### Параметри:
- `--weights` (`-w`): Шлях до вагів PyTorch (`best.pt`).
- `--output-dir` (`-o`): Папка вивантаження планів (за замовчуванням: `models/`).
- `--fp16`: Увімкнення напівточності FP16 (прискорення інференсу у 2.0–2.5 рази на Tensor Cores).
- `--int8`: Увімкнення 8-бітного цілочисельного квантування.
- `--calib-dir`: Каталог репрезентативних зображень для ентропійного калібратора (`IInt8EntropyCalibrator2`).
- `--workspace`: Ліміт пам'яті для побудови тактик TensorRT у МБ (за замовчуванням: 2048 МБ).

## 5. Інтерактивний інтерфейс та автоматизований пакетний скринінг (Batch Triage)

### 1. Робоча станція оператора (Interactive Canvas)
Графічна підсистема побудована на фреймворку `PySide6` з підтримкою апаратного прискорення OpenGL та спеціалізованої ергономічної колірної схеми Slate Dark (`#0f172a`):
- **Відкриття одиночних кадрів:** Підтримка завантаження зображень довільного розміру, включаючи 8K та панорами 13K+.
- **Синтетичний 8K генератор:** Меню `Файл -> Згенерувати 8K тест` генерує повнорозмірний кадр 7680×4320 у пам'яті з тестовими цілями для миттєвої перевірки пропускної здатності без зовнішніх файлів.
- **Плавне масштабування та панорамування:** Апаратно-прискорений в'юпорт (`QGraphicsView` з підтримкою OpenGL):
  - Зум від $0.02\times$ до $50\times$ з фокусуванням по курсору.
  - Кнопка **«100%»** повертає фізичний піксельний масштаб; **«Вписати зображення»** підлаштовує весь кадр під екран.
- **Неруйнівний векторний оверлей:** Рамки цілей малюються косметичним пером зі сталою товщиною лінії 2 px незалежно від наближення.
- **Інтерактивна таблиця цілей:** Вибір будь-якого рядка в таблиці виконує плавне центрування камери на відповідному об'єкті.

---

### 2. Режим автоматизованого пакетного скринінгу (Batch Triage)
Призначений для швидкої фільтрації тисяч аерофотознімків розвідки у фоновому режимі:
- **Запуск:** Меню `Файл -> Пакетний аналіз папки...` або кнопка панелі інструментів.
- **Алгоритм роботи воркера (`BatchTriageWorker`):**
  1. Сканує вхідну директорію на наявність підтримуваних форматів (`.jpg`, `.jpeg`, `.png`, `.tif`, `.tiff`, `.bmp`).
  2. Перевіряє наявність локального кешу метаданих: якщо файл `.json` вже існує, детекція береться з кешу без запуску GPU.
  3. Якщо кешу немає — виконує тайлінг та інференс.
  4. **Логіка фільтрації:** Якщо на знімку знайдено $\ge 1$ ціль, вихідне зображення копіюється у теку призначення (`<folder>_detected`) **прямим системним копіюванням диск-в-диск (`shutil.copy2`)**.
  5. Поруч із зображенням створюється файл кешу `<stem>.json`. Зображення без виявлених цілей відсіюються та не займають дисковий простір.

#### Структура файлу кешу метаданих (`<filename>.json`):
```json
{
  "image_path": "/workspace/data/detected/DJI_20261005_0042.JPG",
  "image_size": [7680, 4320],
  "detections": [
    {
      "bbox": [1420.5, 830.0, 45.0, 32.0],
      "confidence": 0.942,
      "class_id": 2,
      "class_name": "Бронетехніка"
    },
    {
      "bbox": [2810.0, 1940.2, 18.5, 24.0],
      "confidence": 0.885,
      "class_id": 0,
      "class_name": "Легкова техніка"
    }
  ]
}
```
