# Інструкція із запуску модуля наукового бенчмаркінгу системи

Модуль [`scripts/benchmark_system.py`](file:///workspaces/MD/scripts/benchmark_system.py) призначений для автоматизованого збору емпіричних даних швидкодії, декомпозиції латентності, аудиту пам'яті та аналізу ефективності адаптивного тайлінгу для практичного розділу дисертації.

---

## 1. Передумови та підготовка середовища

Перед запуском переконайся, що проєкт зібрано та встановлено всі залежності:

```bash
# 1. Перехід у кореневу директорію проєкту
cd /workspaces/MD

# 2. Надання прав на виконання скрипту (за потреби)
chmod +x scripts/benchmark_system.py

# 3. Перевірка доступності прискорювача GPU
nvidia-smi
```

> [!NOTE]
> Скрипт автоматично виявляє наявність скомпільованого C++20 модуля `pytiling_core` у папках `build/` або `build/bindings/`, а також обирає найкращий доступний бекенд інференсу (`CUDAExecutionProvider`, `TensorRT` або `CPUExecutionProvider`).

---

## 2. Базовий запуск (Стандартний дисертаційний бенчмарк)

Виконує тестування на мультимасштабному наборі панорам (**4K**, **8K**, **13K**), робить по 10 вимірів для кожного масштабу та проводить 50 ітерацій аудиту витоків пам'яті:

```bash
python3 scripts/benchmark_system.py --samples 10 --output-dir reports/benchmark/
```

### Що відбувається під час виконання:
1. **Hardware Discovery:** фіксація конфігурації CPU, RAM, моделі GPU, обсягу VRAM, версії CUDA та провайдерів ONNX Runtime.
2. **Warmup:** прогрів ядра та CUDA-контексту (2 проходи).
3. **Latency Breakdown:** замір кожного етапу ($T_{\text{read}}$, $T_{\text{tiling}}$, $T_{\text{slice}}$, $T_{\text{infer}}$, $T_{\text{remap}}$, $T_{\text{nms}}$, $T_{\text{total}}$) із розрахунком $\mu \pm \sigma$, min, max, $p50, p90, p99$.
4. **Adaptive Tiling Analysis:** розрахунок економії кількості тайлів (порівняння сітки 640 px та адаптивної 736 px).
5. **Zero-PCIe-Readback:** аналіз обсягів передачі даних шиною PCIe (Device-to-Host).
6. **Memory Leak Audit:** 50 послідовних прогонів для перевірки дельти $\Delta\text{RAM} \le 5\text{ MB}$ та $\Delta\text{VRAM} \le 5\text{ MB}$.

## 3. Сценарії використання та приклади команд

### Сценарій А: Експрес-перевірка (швидкий тест за ~5 секунд)
Зменшена кількість прогонів без тривалого тесту на витоки пам'яті:
```bash
python3 scripts/benchmark_system.py \
    --samples 2 \
    --leak-check-iterations 0 \
    --output-dir reports/benchmark_fast/
```

### Сценарій Б: Поглиблений статистичний замір (для публікацій / дисертації)
Збільшена вибірка (30 прогонів на роздільну здатність) для мінімізації дисперсії $\sigma$:
```bash
python3 scripts/benchmark_system.py \
    --samples 30 \
    --leak-check-iterations 100 \
    --output-dir reports/benchmark_thesis/
```

### Сценарій В: Бенчмаркінг на реальному датасеті (наприклад, DOTA)
Тестування на директорії зі справжніми аерофотознімками:
```bash
python3 scripts/benchmark_system.py \
    --input data/sliced_dota/images/val \
    --samples 5 \
    --leak-check-iterations 0 \
    --output-dir reports/benchmark_dota/
```

### Сценарій Г: Бенчмаркінг конкретного одиничного знімка
```bash
python3 scripts/benchmark_system.py \
    --input data/sliced_dota/images/val/P1854_tile_0373_8832_3840.jpg \
    --samples 15 \
    --output-dir reports/benchmark_single/
```

### Сценарій Ґ: Дослідження впливу висоти польоту БПЛА (Евристика $T_{\text{calc}}$)
Зміна розрахункової висоти польоту (впливає на крок перекриття $O_{\text{lap}}$ та розмір сітки):
```bash
# Низька висота (100 м) — менше перекриття
python3 scripts/benchmark_system.py --altitude 100.0 --output-dir reports/benchmark_alt100/

# Велика висота (300 м) — максимальне перекриття цілей
python3 scripts/benchmark_system.py --altitude 300.0 --output-dir reports/benchmark_alt300/
```

## 4. Повний перелік параметрів командного рядка

| Прапорець / Опція | Тип | За замовчуванням | Опис |
| :--- | :---: | :---: | :--- |
| `--samples` | `int` | `10` | Кількість прогонів для кожного кадру для обчислення статистики |
| `--output-dir` | `str` | `reports/benchmark` | Директорія для збереження фінальних звітів (`.json` та `.md`) |
| `--input`, `--image-dir` | `str` | `None` | Шлях до конкретного файлу або папки із зображеннями. Якщо не вказано — генеруються кадри 4K, 8K, 13K |
| `--resolutions` | `str` | `4K,8K,13K` | Перелік роздільних здатностей для синтетичного тесту (`4K`, `8K`, `13K` або розміри на кшталт `7680x4320`) |
| `--altitude` | `float` | `150.0` | Висота польоту БПЛА (в метрах) для адаптивного тайлінгу |
| `--vram-mb` | `int` | `2048` | Бюджет доступної відеопам'яті (MB) для розрахунку формули $T_{\text{calc}}$ |
| `--conf-thresh` | `float` | `0.20` | Поріг впевненості детектора для відсікання фону |
| `--diou-thresh` | `float` | `0.50` | Поріг DIoU для кластеризації меж (Cluster-DIoU-NMS) |
| `--leak-check-iterations` | `int` | `50` | Кількість ітерацій аудиту витоків пам'яті (`0` — пропустити) |
| `--warmup` | `int` | `2` | Кількість попередніх прогонів для прогріву CUDA |

Переглянути вбудовану довідку можна командою:
```bash
python3 scripts/benchmark_system.py --help
```

## 5. Вихідні артефакти та інтерпретація результатів

Після успішного завершення бенчмарку в цільовій директорії формуються два файли:

### 1. `benchmark_summary.md` (Науковий звіт для дисертації)
Файл у форматі Markdown із готовими структурованими таблицями, які можна копіювати прямо в дипломну або наукову роботу:
- **Розділ 1:** Апаратна конфігурація стенду (CPU, RAM, GPU, VRAM, CUDA).
- **Розділ 2:** Наскрізний час кадру $T_{\text{total}}$ та пропускна здатність (FPS).
- **Розділ 3:** Декомпозиція латентності за стадіями ($T_{\text{read}}, T_{\text{tiling}}, T_{\text{slice}}, T_{\text{infer}}, T_{\text{remap}}, T_{\text{nms}}$).
- **Розділ 4:** Квантильний аналіз ($p50, p90, p99$) для оцінки стабільності в реальному часі.
- **Розділ 5:** Ефективність адаптивного тайлінгу 736 px порівняно з базовим 640 px (економія тайлів ~22–25%).
- **Розділ 6:** Аналіз шини PCIe та інваріанту Zero-PCIe-Readback (економія D2H трафіку > 99.99%).
- **Розділ 7:** Результати аудиту стабільності та відсутності витоків пам'яті.
- **Розділ 8:** Формалізовані наукові висновки.

### 2. `benchmark_results.json` (Структуровані дані)
Містить усі сирі заміри, конфігурацію запуску та квантилі. Призначений для побудови графіків у Python/Matplotlib/Seaborn або імпорту в електронні таблиці.
